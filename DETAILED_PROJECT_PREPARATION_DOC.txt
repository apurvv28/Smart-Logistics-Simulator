2) PROJECT IN SIMPLE WORDS
============================================================
LogiCore is a logistics simulation system with 3 phases:

Phase 1 (Inter-City Routing):
- Finds best path between major cities using graph algorithms.
- Focus is national-level route optimization.

Phase 2 (Intra-City Last Mile + Multi-Stop):
- Simulates package movement inside city roads.
- Uses nearest-neighbor style logic for multiple deliveries.
- Can use road geometry (OSRM) for practical path visualization.

Phase 3 (End-to-End Integration + UI):
- Combines Phase 1 and Phase 2 into one smooth journey.
- User can see the full flow from city-to-city to local delivery.

Architecture overview:
- Backend: Java 17 + Spring Boot 3.3.5
- Frontend: React 18 + Vite
- Real-time telemetry: WebSocket (STOMP + SockJS)
- Mapping and visualization: Leaflet, D3, force graph tools

5) TECH STACK USED, WHY USED, AND HOW TO SCALE
============================================================
Below is the project tech stack with clear purpose and scaling path.

------------------------------------------------------------
5.1 BACKEND STACK
------------------------------------------------------------
1) Java 17
Use in this project:
- Main language for core logistics engine and algorithms.
Why suitable:
- Strong performance, mature ecosystem, stable for enterprise systems.
How to scale:
- Run multiple backend instances.
- Use JVM tuning and proper garbage collector settings.
- Add distributed caching for heavy route computations.

2) Spring Boot 3.3.5
Use in this project:
- REST API layer, dependency injection, app configuration.
Why suitable:
- Fast development, clean architecture, production-ready tools.
How to scale:
- Deploy as containerized microservices.
- Add API gateway and service discovery.
- Horizontal scaling behind load balancer.

3) spring-boot-starter-web
Use in this project:
- HTTP REST endpoints for simulation requests.
How to scale:
- Stateless APIs so multiple instances can run in parallel.
- Add rate limiting and request throttling.

4) spring-boot-starter-validation
Use in this project:
- Input validation for safer API contracts.
How to scale:
- Keep strict schema validation to reduce bad-request load.
- Add centralized validation error analytics.

5) spring-boot-starter-websocket + STOMP
Use in this project:
- Real-time telemetry updates to frontend dashboard.
How to scale:
- Move from simple in-memory broker to external broker (RabbitMQ/Kafka).
- Use sticky sessions or distributed websocket gateway.
- Partition telemetry channels by simulation/session ID.

6) Graph Algorithms (Dijkstra, Bellman-Ford, Floyd-Warshall, A* Search)
Use in this project:
- Core route optimization logic.
How to scale:
- Precompute frequently used routes.
- Use adjacency-list optimizations and caching.
- For very large graphs, use distributed graph engines or sharded graph data.

7) Greedy Nearest-Neighbor (multi-stop)
Use in this project:
- Fast approximate solution for multi-stop delivery.
How to scale:
- Upgrade to advanced solvers (2-opt, 3-opt, OR-Tools).
- Add constraints: time windows, capacity, traffic.
- Run optimization jobs asynchronously.

8) OSRM integration
Use in this project:
- Road-accurate path details for map simulation.
How to scale:
- Use local/self-hosted OSRM for higher control.
- Add retry + fallback routing provider.
- Cache route responses by geo-hash and segment.
